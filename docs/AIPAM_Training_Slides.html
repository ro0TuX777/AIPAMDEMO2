What is AIPAM?

An AI-driven network forensics platform that automates threat detection

🔍 Automatic Malware Detection

Upload any PCAP file and AIPAM automatically analyzes network traffic to identify malware, C2 communication, data exfiltration, and more.

💬 AI Chat Assistant

Ask follow-up questions in plain English — get cited, evidence-backed answers grounded in the actual analysis data.

📊 Automated Reports

Generate analyst or executive reports with MITRE ATT&CK mappings, IOC lists, attack timelines, and remediation steps.

🔒 100% Air-Gapped

Runs completely offline. No data ever leaves your network. The AI model runs locally via Ollama.

Who Is This For?

  • Security Analysts — faster threat analysis and investigation
  • SOC Teams — reduce investigation time with automated triage
  • Incident Responders — quick malware identification and containment guidance
  • Security Researchers — study network-based threats with AI assistance

Tab Deep Dive — Analysis & Triage

The tabs that help you understand what happened and prioritize investigation

🔎 Investigate (Investigation Queue)

Your starting point for analyst review. This unified queue merges findings, alerts, and theories into a single priority-ranked list.

  • Composite score — weighted blend of severity (25%), confidence (20%), corroboration (20%), blast radius (15%), recency (10%), and feedback history (10%)
  • Status workflow: Unreviewed → Confirmed / False Positive / Needs Review / Deferred
  • Evidence Drawer — click any row to expand and see host context, related IOCs, connections, and timeline
  • Bulk actions — select multiple items and confirm/dismiss/escalate at once
  • Filters — by type (finding/alert/theory), severity, MITRE tactic, host, corroboration status
Why it matters: Instead of jumping between alerts, findings, and theories separately, the Investigation Queue gives you one ranked list sorted by urgency — so you always work on the most critical item first.

💡 Theories (Theory of the Case)

Automatically generates and ranks attack hypotheses from evidence — 100% deterministic, no LLM hallucination.

  • Hypothesis types: C2 Beaconing, Data Exfiltration, Malware Delivery, Reconnaissance, Lateral Movement, Admin Tools, Ransomware, Credential Theft, Benign/Normal
  • Each theory shows a score (0–100%) and confidence level (High/Medium/Low)
  • Supporting vs Contradicting evidence displayed as clickable chips linking to specific alerts, findings, and IOCs
  • Score breakdown — see exactly how the score was computed (% from findings, alerts, IOCs)
  • "Explain" button — get an LLM-powered plain-language explanation of the theory
  • Host-scoped — switch to per-host view to see what theories apply to a specific IP
Why it matters: Theories answer the "big picture" question: "What type of attack is this?" The ranked list helps analysts quickly identify the most likely scenario and focus investigation.

🧩 Slices (Incident Slices)

Groups related alerts, findings, and connections into logical attack threads — showing which events belong together.

  • Grouping logic: seeded from community_id (network conversation), merged by shared host IPs + time proximity
  • Types: Attack Thread, Recon Phase, C2 Session, Lateral Movement, Exfiltration, Misc
  • Each slice shows: severity, confidence bar, time range, member alerts/findings/IOCs as clickable chips
  • Cross-linked to Theories — see which theories this slice supports
  • Severity distribution chart at the top for quick overview
Why it matters: Raw alerts are noisy. Slices group related events into coherent "attack threads" so you can see "these 5 alerts + 2 findings are all part of the same C2 session" instead of reviewing them individually.

⚡ Why Unusual? (Annotations)

Shows statistical outliers — hosts whose network behavior deviates significantly from the job-wide baseline.

  • Metrics analyzed: connection count, bytes sent/received, unique destinations, unique services, alert rate, DNS query count, finding count
  • Deviation gauge — visual comparison of observed value vs baseline (e.g., "12× more connections than median")
  • Baseline comparison bar — side-by-side chart showing this host vs the population
  • Group by host toggle — see all anomalies for each host together
  • Related evidence — linked alerts and findings that explain why this host stands out
Why it matters: Even without IDS alerts, a host sending 50× more data than average is suspicious. Annotations surface these statistical anomalies that rule-based detection might miss.

Tab Deep Dive — Context & Narrative

Tabs that help you visualize, reconstruct, and document the attack

📖 Storyline (Kill-Chain Reconstruction)

Reconstructs the attack as a kill-chain narrative — mapping evidence to stages like Reconnaissance → Delivery → Exploitation → C2 → Exfiltration.

  • Stages: Each kill-chain phase shows node/edge counts, confidence score, summary, and involved host IPs
  • Host timelines — see which stages each host participated in and when
  • Auto-generated narrative — a plain-English reconstruction: "At 14:32, host 10.0.0.5 initiated reconnaissance…"
  • Time-bounded — each stage includes start/end timestamps for temporal analysis
Why it matters: Storyline transforms scattered evidence into a coherent chronological narrative — essential for incident reports and briefing leadership on "what happened."

🕸️ Graph (Attack Graph)

An interactive D3 force-directed graph that visually connects hosts, IOCs, alerts, findings, and files.

  • Two modes: Evidence Graph (relationships between all evidence types) and Topology (network communication map)
  • Interactive — drag, zoom, click nodes to see details, filter by node type
  • Color-coded — node colors indicate type (host=blue, IOC=red, alert=amber, finding=purple)
  • Narrative button — generates an LLM-powered description of the graph relationships
  • Export — save the graph as a PNG image for reports
Why it matters: The graph answers "how is everything connected?" at a glance — revealing lateral movement paths, shared IOCs, and multi-host attack patterns that tables cannot show.

🔗 Correlations (Log ↔ PCAP Matching)

Links host telemetry logs to network-level PCAP evidence using temporal proximity matching.

  • Temporal matching — correlates log events with network connections that occurred within configurable time windows
  • Cross-source — bridges the gap between endpoint logs (syslog, event logs) and network captures
  • Confidence scoring — each correlation includes a match confidence based on time proximity and shared hosts
Why it matters: Attackers leave traces in both logs and packets. Correlations automatically link these disparate data sources so you don't miss connections.

📋 Build Case (Proof Builder)

The analyst's evidence curation workspace for building formal incident narratives.

  • Pin evidence — drag alerts, findings, IOCs, and theories into your proof with roles: Supports Contradicts Context
  • Three narrative modes:
    • SOC Handoff — Key Findings, Affected Systems, Recommended Actions
    • IR Technical — Attack Path, Indicator Analysis, MITRE Mapping, Containment
    • Executive Summary — Business Impact, Risk Assessment, Remediation Status
  • Generate narrative — LLM renders a polished markdown report from your curated evidence
  • Export — download as Markdown or HTML for archival or handoff
Why it matters: Build Case bridges the gap between analysis and documentation. Instead of manually writing incident reports, you curate evidence and let the AI generate a structured narrative.

📦 Artifacts (Evidence Packages)

Downloadable self-contained ZIP bundles containing all evidence for a job — for archival, legal hold, or handoff to other teams.

  • Contents: alerts JSON, findings JSON, IOCs, host summaries, extracted files, PCAP metadata, reports
  • Offline-ready — everything needed to review the case without access to AIPAM
  • Chain of custody — includes SHA-256 hashes and timestamps for integrity verification
Why it matters: When you need to share findings with external teams, legal, or management, Artifacts give you a complete, portable evidence package.

Creating an Analysis Job

Three ways to get PCAPs into AIPAM for analysis

Method 1: Direct Upload (Most Common)

  1. Navigate to New Analysis in the top nav
  2. Drag & drop your PCAP/PCAPNG files (or click to browse). Supports multiple files.
  3. Choose an Execution Profile (see table below)
  4. Optionally add a Job Name and Notes for context
  5. Click Start Analysis — the job is queued and processing begins

Method 2: Pull from Security Onion

If Security Onion integration is configured, specify a time range and sensor filter — AIPAM exports matching packets directly from SO and creates a job automatically.

Method 3: Pull from Arkime

If Arkime is enabled, specify an Arkime filter expression and time range — AIPAM exports matching sessions as PCAP and starts analysis.

Execution Profiles

ProfileSensors RunUse CaseEstimated Time
Triage Zeek, Suricata, TLS Enrich, TI Matcher Quick alert check — is this traffic interesting? ~1–3 minutes

💡 Tip: Start with Triage for a quick look. If interesting, you can re-analyze the same job with Standard or Deep without re-uploading the PCAP.

Real-Time Progress

While a job is running, the Job Detail page shows live pipeline progress via Server-Sent Events (SSE). You'll see each stage transition from pending → running → completed, and get early alert toasts for critical findings as they're discovered.

Investigation Workflow

How to work through an analysis job once it completes

  1. Start with the Summary — Read the headline, threat level, and top signals. This tells you whether the traffic is interesting.
  2. Check Alerts — Review Suricata IDS alerts sorted by severity. Critical and high alerts need immediate attention.
  3. Examine Findings — AI-generated findings explain what was found and why it matters. Each finding includes MITRE ATT&CK technique mappings and a confidence score. Click "Explain" for an AI-powered plain-language explanation.
  4. Investigate Hosts — Drill into specific hosts. Each host page shows connections, DNS queries, TLS sessions, alerts, and extracted files for that host.
  5. Review IOCs — Check Indicators of Compromise: malicious IPs, domains, file hashes, JA3 fingerprints. These can be exported to your blocklists.
  6. Explore the Timeline — See events in chronological order to understand the attack sequence.
  7. Read Theories — AI-generated attack theories provide narrative explanations of what likely happened and which MITRE techniques were used.
  8. Use the Attack Graph — The visual graph connects hosts, alerts, findings, and IOCs to show relationships at a glance.

Investigation Queue — HITL Review

The Investigation Queue is a human-in-the-loop (HITL) workflow where analysts triage findings and alerts:

Status Labels

New Needs review
In Progress Under investigation
Confirmed Verified true positive
False Positive Ruled out
Escalated Sent to senior analyst

Why HITL Matters

AI findings are suggestions, not verdicts. The investigation queue ensures every significant finding gets human review before it's included in reports or used to generate detection rules. Analyst decisions feed back into model training.

AI Chat Assistant

Interactive investigation powered by RAG (Retrieval-Augmented Generation)

How It Works

The chat assistant is scoped to the current job's data. It uses a 3-source retrieval strategy:

  1. Structured DB Lookup — Extracts IPs, finding IDs, MITRE techniques from your question and queries the database directly
  2. Semantic Vector Search — Uses embeddings to find relevant evidence chunks from the analysis
  3. Knowledge Base — Searches any analyst-uploaded documents (asset inventories, network diagrams, policies)

Every response includes citations linking back to specific alerts, findings, hosts, or KB documents so you can verify the AI's claims.

Example Questions

💬 "What hosts are communicating with known malicious IPs?"

💬 "Identify any command-and-control (C2) communication patterns"

💬 "Is there evidence of data exfiltration?"

💬 "Which hosts have the most suspicious activity?"

💬 "Explain finding FND-abc123 in simple terms"

💬 "What MITRE ATT&CK techniques were observed?"

💡 Features: Streaming responses (tokens appear in real-time) • Conversation persistence (pick up where you left off) • Suggested follow-up questions • Evidence references with clickable links • Context-scoped to specific findings, hosts, or the full job

Integrations

Connect AIPAM to your existing security stack

🧅 Security Onion

Pull PCAPs: Specify a time range and sensor filter — AIPAM authenticates to SO, creates a PCAP job, downloads the result, and starts analysis automatically.

Push Results: Click "Push to Security Onion" on any completed job to upload PCAPs for re-analysis by SO's Suricata + Zeek stack.

Configure in Settings → Integrations: URL, username, password

🦌 Arkime

Import to Arkime: Click "Import to Arkime" on any completed job. AIPAM queues the PCAP for the Arkime importer, which indexes sessions into OpenSearch.

Pivot Links: On any alert or finding, click the Arkime pivot button to open the relevant session directly in the Arkime viewer.

Enable with: docker compose --profile arkime up -d

📝 Detection Rules

Suricata Rules: AI-generated Suricata IDS rules from confirmed findings — ready to deploy to your sensors.

Sigma Rules: Vendor-agnostic detection rules in Sigma YAML format for cross-platform deployment.

YARA Rules: Manage YARA rule sets used by the File Triage sensor for file-based detection.

🔌 REST API

Full REST API with 80+ endpoints. Automate job creation, retrieve findings programmatically, integrate with SOAR platforms, or build custom dashboards.

API docs: http://<server>:8000/api/v1/docs

Tips & Best Practices

Get the most out of AIPAM

🎯 Start with Triage

Use the Triage execution profile first. It runs in 1–3 minutes and tells you if the traffic is worth deeper analysis. Re-analyze with Standard or Deep only if needed.

📝 Add Context

Upload network diagrams, asset lists, and security policies to the Knowledge Base. The AI Chat uses these to provide environment-specific answers.

✅ Triage Findings

Use the Investigation Queue to mark findings as Confirmed, False Positive, or Escalated. This builds training data that improves the AI over time.

🔗 Use Pivot Links

When Arkime is enabled, use pivot links on alerts and findings to jump directly to the raw packet view for deep-dive analysis.

💬 Ask the AI

Don't just read the findings — use the AI Chat to ask "what happened?", "is this a real threat?", or "what should I do next?" The more specific your question, the better the answer.

📦 Export Evidence

Use the Proof Builder for formal incident reports. Use Evidence Packages for archival or handoff to other teams. Both are self-contained and offline-ready.

🔄 Keep Rules Updated

Periodically update Suricata and YARA rules via the Detection Rules page. On air-gapped systems, transfer rule files via USB/removable media.
